# Storefront mode and platform boundaries

Current configuration, 2026-10-08: normal storefront mode is active. `demo_mode` defaults to `false` and is explicitly false in checked settings. Seven native content pages now exist. Current live browser acceptance and publication are recorded in TESTING.md; historical development checks do not establish current live status.

The optional legacy guard, when explicitly enabled, adds localized sample notices and disables theme-generated checkout/personal-information forms, claims and structured data. This optional source behavior is inactive in the current storefront. Free-shipping progress separately requires merchant policy verification and matching shop/cart currencies; the theme does not invent an exchange rate.

If the optional legacy mode is enabled, the cart remains usable for browsing while theme-generated checkout controls are removed. This inactive setting does not configure Shopify's checkout, disable a direct Shopify checkout URL, change payment test/live mode, or control an installed app's checkout UI. The merchant must separately verify Shopify platform checkout and payments settings before accepting real orders.

The built-in Shopify native newsletter and wholesale/contact forms are not rendered in demo mode. Cart note and gift-note inputs, article comment submission, and theme-rendered customer account, registration, address, login, recovery, activation, reset, and order-detail flows are replaced by a localized notice while demo mode is on. This also hides account/order details rendered by the theme. With demo mode turned off, the existing native Shopify flows return; the theme no longer forwards sign-ups to Klaviyo. These guards cover forms and customer data rendered by these theme files. They cannot disable app embeds, externally injected forms, pixels, or other Shopify platform surfaces.

Only the optional legacy mode displays a persistent notice or guards classic customer templates. The current normal storefront displays neither restriction. A branded native password template replaces the old stub. Shopify may impose its own partner-development gate regardless of the theme template; removing that restriction requires a platform entitlement change. Shopify-hosted customer account and checkout surfaces may bypass theme rendering. Optional theme guards do not disable those hosted routes or third-party flows.

The Grove footer uses Shopify's localization form for the currently enabled countries and links to Shopify's native consent preferences UI when the public `privacyBanner.showPreferences()` bridge is available. It does not create a second consent mechanism or write consent. If Shopify's bridge is absent, the footer reports that the native preferences UI is unavailable.

Dynamic theme UI can read `body.dataset.demoMode`, `body.dataset.demoSamplePrice`, and `body.dataset.demoCheckoutDisabled`. Copy lives in the English and Arabic locale files. App-provided/dynamically injected product cards remain outside this theme setting unless the app explicitly consumes these attributes.
