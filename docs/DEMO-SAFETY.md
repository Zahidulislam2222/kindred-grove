# Demo mode and storefront boundaries

Implementation status, 2026-09-24: Phase 2 accepted for the reviewed development artifact. Integrated browser checks passed 41 cases with zero failures and five documented skips; local security/configuration tests passed 95/95. All 150 local/frozen/downloaded theme files match. Actual cart, consent, header/video, no-JavaScript navigation and narrow product reflow checks passed. Quiz/Wholesale alternate-template functional checks and active axe checks each passed 2/2. Canonical Quiz/Wholesale resources remain absent; hosted accounts/checkout and platform/app processing remain outside theme controls. See [the acceptance record and limits](../BUILD-PLAN.md#phase-2--safe-functional-demo-storefront).

The local theme setting `demo_mode` defaults to `true` and is explicitly true in the checked-in theme settings data. When enabled, the layout displays a persistent localized notice, product prices are labeled as samples, theme checkout controls are disabled, built-in contact/newsletter forms are replaced with informational text, and the theme omits its JSON-LD and product price/availability metadata. Theme trust badges, optional FAQ claim content, review/certification blocks, sale/comparison claims and free-shipping progress are hidden in this mode. Outside demo, free-shipping progress defaults off and requires merchant policy verification plus matching shop/cart currencies; the theme does not invent an exchange rate.

The cart remains usable as a storefront preview: visitors can add and remove sample items and see sample totals. The demo setting removes checkout submission controls rendered by this theme. It does not configure Shopify's checkout, disable a direct Shopify checkout URL, change payment test/live mode, or control an installed app's checkout UI. Do not enter personal or payment data in the demo. The merchant must separately verify Shopify platform checkout and payments settings before accepting real orders.

The built-in Shopify native newsletter and wholesale/contact forms are not rendered in demo mode. Cart note and gift-note inputs, article comment submission, and theme-rendered customer account, registration, address, login, recovery, activation, reset, and order-detail flows are replaced by a localized notice while demo mode is on. This also hides account/order details rendered by the theme. With demo mode turned off, the existing native Shopify flows return; the theme no longer forwards sign-ups to Klaviyo. These guards cover forms and customer data rendered by these theme files. They cannot disable app embeds, externally injected forms, pixels, or other Shopify platform surfaces.

The storefront layout contains the persistent notice. The minimal native `layout/password.liquid` stub is retained verbatim and does not add that notice to Shopify’s password gate. Classic customer templates in this theme are guarded, while Shopify-hosted customer account and checkout surfaces may bypass theme rendering. The demo-mode notice and form guards are not claims that all those hosted routes or third-party flows are disabled.

The Grove footer uses Shopify's localization form for the currently enabled countries and links to Shopify's native consent preferences UI when the public `privacyBanner.showPreferences()` bridge is available. It does not create a second consent mechanism or write consent. If Shopify's bridge is absent, the footer reports that the native preferences UI is unavailable.

Dynamic theme UI can read `body.dataset.demoMode`, `body.dataset.demoSamplePrice`, and `body.dataset.demoCheckoutDisabled`. Copy lives in the English and Arabic locale files. App-provided/dynamically injected product cards remain outside this theme setting unless the app explicitly consumes these attributes.
