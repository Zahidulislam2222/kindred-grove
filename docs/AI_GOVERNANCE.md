# AI-assisted engineering governance

Updated 2026-09-24. This describes the current project workflow. Earlier assistant names, tool-access limitations, blanket review assertions and automatic-deployment claims are historical and are not evidence of the present environment.

## Responsibilities

The user requested Astra/root for architecture, monitoring and review, with Luna handling bounded implementation tasks in parallel. Related tasks belong to one delivery milestone with a combined acceptance gate. Parallel assignments have explicit file ownership and cannot independently deploy an unfinished shared worktree.

The root agent reads the current rules, project state and evidence; writes acceptance criteria before significant implementation; researches platform behavior from official sources; and reviews integration and real flows. A reviewer who did not author a change checks it against the criteria. Independent AI review is not human approval or a legal/security certification.

## Authorization and access

Follow the user's current authorization and global rules. Available CLIs, connected browser sessions and platform APIs may be used within that scope after verifying the actual connection and target. Never infer unavailable access from a historical tool list, or infer deployment permission from possessing a credential.

No paid resources, metered services, new payment-backed subscriptions, real orders or external messages are part of this build. Required spending decisions must stop with the user's explicit cost-warning procedure. Routine reversible implementation and authorized read-only discovery do not need repeated confirmation.

The current handoff authorizes committing and pushing reviewed public source/documentation, then updating the existing client Google Doc and PDF. Live redesign publication is a separate decision. Local release workflows fail closed before writes while reusable remote drift/parity automation is incomplete. Environment and branch protections must be observed through native platform state before claiming they enforce anything.

## Engineering gates

- Write concrete criteria or a failing reproduction first.
- Use one configuration owner per value and contextual input/output defenses; never put real secrets in source or tests.
- Preserve security scan hooks. Fix findings rather than suppressing checks.
- Run relevant automated gates and exercise the real flow; record failures, missing gates and skips separately.
- Obtain independent review, freeze the reviewed artifact, check remote drift, deploy only within authorization and prove pulled parity.
- Record escaped defects and improve the gate that missed them. Update the project checkpoint before and after notable work so power loss does not erase task state.

Human review remains a release/merge responsibility. Do not assert that a human approved a diff merely because an agent reviewed it. Do not invent a model-specific commit trailer; record only the tooling actually used when attribution is requested.

## Data and recovery

Credentials remain in approved local/platform secret storage and the ignored recovery record. The private dossier contains the durable project narrative without secrets; ignored project memory contains working checkpoints. Public docs are scrubbed outputs, not copies of private infrastructure or customer records.

No real customer data is needed for the demo's tests. Use synthetic fixtures and isolated carts; avoid recording password entry or complete cookie/request payloads. Do not claim that provider retention/training settings are known without checking the active account and product. Client Google Docs and `my-project-view/` artifacts are edited only on an explicit request; the current handoff includes that authorization. They are not committed with public source.

## Evidence and cost honesty

The workflow can allocate routine work to a cheaper model, but both agents consume usage and coordination adds overhead. This project has no verified account-usage meter or measured model-cost saving. Do not report invented quota percentages, time saved, manual-build comparisons or universal reliability claims.
